# Catwalk — შიდა სისტემის ტექნიკური დავალება (v2 · 26.07.2026)

> ორიგინალი. ცვლილებები: იხ. `00-changes-since-v2.md`. ინდმეწარმის ნაწილი აღარ მოქმედებს.

## 1. ბიზნეს-კონტექსტი
Instagram-ზე დაფუძნებული pre-order მოდის პლატფორმა თბილისში, 5 წლისაა, ~30K follower + Catwalk Men (~2K). თვეში ~430 შეკვეთა, საშუალო ჩეკი ~400 ₾, GMV ~172,000 ₾/თვე. კლიენტი ირჩევს ნივთს ევროპული საიტიდან (Yoox, BestSecret, Zalando, Zalando Lounge, Veepee, Cettire, LuisaViaRoma), Catwalk უკვეთავს, გერმანიის გადამზიდით ჩამოდის (~14-21 სამუშაო დღე), კლიენტი იხდის ფასს + წონის ტარიფს (XS 15 / S 20 / M 30 / L 45 ₾).

გუნდი: ანაკო (Operations Manager) · გვანცა (ლოჯისტიკა) · 5 გამყიდველი (ტელეფონით, IG DM) · Marketing Manager (სექტემბრიდან).
ინფრასტრუქტურა: ერთი Google Sheet, Notion, Instagram DM, Flitt, catwalk.ge.

## 2. პრობლემები
- გუნდის დროის ~40% ხელით შეყვანა/მონიშვნა
- გაუქმების #1 მიზეზი: სთორისა და გამოწერას შორის ნივთი/ზომა ქრება
- მარჟის კონტროლი არ არსებობს: markup 6%-545%; ივნისში ფასების სვეტი აირია, 6 კვირა ვერავინ შეამჩნია
- კლიენტების ბაზა არ არსებობს: ~1,100 მყიდველი, განმეორებითი 26%
- ბონუსების ატრიბუცია ემოჯიზე დგას

პრინციპი: DM რჩება გაყიდვის არხად. სისტემა DM-ის უკანაა.

### Client
username (IG), phone (სავალდებულო), sizes, orders[], ltv, segment (auto: 2+ = განმეორებითი; GMV ტოპ 10% = VIP), wishlist[], notes.
### Payment
order_id, amount, type (item/weight), matched (auto/manual), source (bank/flitt), date.
### BonusLedger
order_id, seller_id, amount = contribution × 15% (სფლითზე 7.5/7.5), month, approved_by.

## 4. ეტაპები
### ეტაპი 1 — MVP (30.09)
- **E1 შეკვეთის ფორმა.** ტელეფონიდან ≤60 წამში: კლიენტი (ბაზიდან/ახალი, ტელეფონი სავალდებულო), ლინკი, ზომა, cost, ფასი, მაღაზია, ავტორი/სფლითი, ბრენდი → to_order. კრიტერიუმი: ხელით შეყვანა ქრება.
- **E2 ლინკის ჩეკერი.** გვერდი ცოცხალია? ზომაა? ფასი ემთხვევა? ✅/⚠️/❌. წითელზე არ ინახება. + დილის ავტო-გადამოწმება. bot-დაცვა: headless + როტაცია ან თითო საიტზე ცალკე; ვერ მოწმდება = „ხელით გადაამოწმე". კრიტერიუმი: „ნივთი აღარ იყო" ≤2%.
- **E3 მარჟის იატაკი.** contribution ცოცხლად; markup < 45% ან contribution < 0 → არ ინახება; მენეჯერის override ლოგით. კრიტერიუმი: 0 ზარალიანი შეკვეთა override-ის გარეშე.
### ეტაპი 2 (15.10)
- **E4 სტატუსის შეტყობინებები.** დილის სია: მე-10 დღეს აფდეითი · ჩამოსვლისას წონა · გაგზავნისას ტრეკინგი. მზა ტექსტი, ერთი ღილაკით კოპირება, ადამიანი გზავნის. + 1-კითხვიანი გამოკითხვა. კრიტერიუმი: „ვის მივწერო" ქრება.
- **E5 ჩარიცხვების დაწყვილება.** ბანკის ამონაწერი (API ან CSV) + Flitt webhook → ავტო-დაწყვილება → დაუწყვილებელი მენეჯერთან. კრიტერიუმი: ≥80% ავტო.
- **E6 ტრანზიტული აღრიცხვა.** კლიენტის ფული და საკომისიო ცალ-ცალკე; თვის ჯამები. ექსპორტი Sheets/CSV ყოველდღე. [გადასაწერია შპს-ზე]
### ეტაპი 3 (31.10)
- **E7 კლიენტების ბაზა.** მიგრაცია (~1,100), პროფილი + სეგმენტები + wishlist + ექსპორტი WhatsApp კამპანიისთვის. კრიტერიუმი: სრული სურათი 10 წამში.
- **E8 ბონუსები.** BonusLedger ავტო, თვის რეპორტი. კრიტერიუმი: დავა 0.
- **E9 დაფა.** ანაკოს ხედი + „პარასკევის ანგარიში" (7 სტრიქონი) + ნინოს ხედი (15 წამი). sanity-ალერტები.
### ეტაპი 4 (15.12)
- **E10 სქრეიპინგი საიტისთვის.** [ახლა Catalog Engine, იხ. v3]
- **E11 Sales Copilot.** upsell + რთული ქეისის დრაფტი; არასდროს გზავნის თვითონ. ტესტი: 20 ჩატი, <70% = არ შენდება. კრიტერიუმი: გამოყენება ≥30%, ჩეკი +10%.
