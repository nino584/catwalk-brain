# ADR 0003: მარჟის იატაკი, ჩამოსვლის ვადა, პასუხის დრო

სტატუსი: **მიღებული** · 05.09.2026 · ნინო

სამივე გადაწყვეტილება მიღებულია იმ გაზომვების საპასუხოდ, რომლებიც 2,746 ჩატისა
და 940 შეკვეთის დამუშავებამ აჩვენა.

---

## 1. E3 — მარჟის იატაკი რჩება **45%**

**გადაწყვეტილება:** `markup < 45%` → შეკვეთა არ ინახება. მენეჯერის override ლოგით.
სპეციფიკაცია უცვლელი რჩება.

**რას ნიშნავს პრაქტიკაში.** 08–09.2026-ის 438 შეკვეთიდან:

| | |
|---|---|
| Markup მედიანა | 55% |
| **45%-ზე დაბალი** | **160 (36%)** |
| მინიმუმი | −9% |

ანუ E3-ის ჩართვისას **ყოველი მესამე შეკვეთა დაიბლოკება** და override-ს მოითხოვს.
ეს შეგნებული არჩევანია, არა გვერდითი ეფექტი.

**ვისზე მოხვდება პირველ რიგში:**

| საიტი | მედ. markup | შეკვეთა |
|---|---|---|
| cettire.com | **14%** | 22 |
| farfetch.com | **21%** | 11 |
| glamood.com | 30% | 7 |
| jomashop.com | 43% | 7 |
| gilt.com | 44% | 5 |

Cettire და Farfetch თითქმის მთლიანად იატაკის ქვემოთ არიან. ესენი ყველაზე ძვირ
ნივთს ყიდიან — Cettire-ის მედიანური ფასი 1,407 ₾, 22 შეკვეთა და 27,847 ₾ ბრუნვა.

**შედეგი:** ძვირი ნივთის შესყიდვა ავტომატურად აღარ გაივლის — ყოველ ჯერზე
ცნობიერი გადაწყვეტილება და ლოგში ჩანაწერი დარჩება. სწორედ ეს იყო E3-ის მიზანი.

**რისკი:** თუ override ყოველდღიური რუტინა გახდება, წესი აზრს კარგავს.
საზომი: override-ების წილი. თუ თვეში 30%-ს გადააჭარბებს, იატაკს დავუბრუნდებით.

## 2. ჩამოსვლის ვადა რჩება **14 სამუშაო დღე**

**გადაწყვეტილება:** კლიენტს ვეუბნებით 14 სამუშაო დღეს. `templates/03-shekvetis-piroba`
უცვლელი რჩება.

**რას ამბობს გაზომვა.** 421 შეკვეთაზე, პირობების გაგზავნიდან „თქვენი შეკვეთა
ჩამოვიდა"-მდე:

| | |
|---|---|
| მედიანა | **25 კალენდარული დღე** |
| 21 დღეზე მეტი | 290 (68%) |
| დაპირება | 14 სამუშაო ≈ 20 კალენდარული |

ანუ ვადა შენარჩუნებულია მაშინ, როცა რეალობა მას სისტემურად სცდება.

**რა ხდება ამის შედეგად:** „გაიწელა" უკვე გაუქმების მიზეზია 35 ჩატში.

**რაც აქედან სავალდებულო ხდება.** რადგან ვადა არ იზრდება, **დაგვიანების
შეტყობინება ვეღარ იქნება არჩევითი.** `templates/07-dagvianeba` დღეს მხოლოდ
110-ჯერ გამოიყენა — ანუ დაგვიანების უმეტესობა კლიენტს არ ეცნობება.

წესი: **მე-15 სამუშაო დღეს, თუ ნივთი არ ჩამოსულა, კლიენტს ეგზავნება
`templates/07-dagvianeba` — პროაქტიულად, სანამ ის იკითხავს.**
E4-ის დილის სიაში ეს ავტომატურად უნდა ჩნდებოდეს.

**საზომი:** „გაიწელა" გაუქმებების რაოდენობა. თუ არ დაეცემა, ვადას დავუბრუნდებით.

## 3. N2/N14 — პასუხის ზღვარი **30 → 45 წუთი**

**გადაწყვეტილება:** კლიენტს პასუხი ეცემა **45 წუთში**, არა 30-ში.

⚠️ **ეს ცვლილება ჯერ ორიგინალ დოკუმენტში უნდა შევიდეს** (`catwalk-jarimebi-v2.md`,
Google Docs) — თქვენივე წესით: ჯერ დოკუმენტში, მერე ჩატში. რეპოში უკვე ასახულია
(`docs/brain/rules/02-jarimebi.md`, `03-pasuxis-dro.md`), მაგრამ წყარო ჯერ ძველია.

**რას ცვლის ციფრებში** (15.08–03.09, 5,407 გაზომილი პასუხი):

| ზღვარი | დარღვევა | წილი |
|---|---|---|
| 30 წთ | 877 | 16.2% |
| **45 წთ** | **719** | **13.3%** |
| 60 წთ | 621 | 11.5% |

**18%-ით ნაკლები.** რეალური გაუმჯობესებაა, მაგრამ მასშტაბს არ ხსნის:
719 ჯარიმა ორ კვირაში, მეინსაც და ბექსაც, პროგრესიით 50→200 ₾ — ხელფასიდან
დაქვითვის 50%-იან ლიმიტს მრავალჯერ სცდება.

**რატომ არ შველის ზღვარის გაწევა.** განაწილება ასეთია: p50 = 3 წთ, p75 = 17 წთ,
p90 = **188 წთ**. ანუ პრობლემა 30-45 წუთის ზონაში არ არის — ის კუდშია, სადაც
საათებია. 45 წუთი მხოლოდ იმ 158 შემთხვევას ჭრის, რომელიც ისედაც ზღვართან იყო.

**ღია რჩება:** ან სამუშაო საათები უფრო ვიწროა, ვიდრე გაზომვაში (16 საათი აღებული),
ან წესი პრაქტიკაში სრულად არ აღსრულდება. ანაკოსთან გასარკვევია.

**ჩემი წინადადება ძალაში რჩება:** სისტემამ ღია ჩატები ცოცხლად აჩვენოს.
719 ჯარიმა გუნდს ვერ გამოასწორებს; ეკრანზე გამოტანილი 719 ღია ჩატი კი გამოასწორებს.
